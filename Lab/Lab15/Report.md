# Report

## 1

![1](/screenshots/1.png)

PHP-FPM в Docker разделяет ответственность: Nginx обслуживает HTTP, статику
и проксирование, а PHP-FPM выполняет PHP-код как отдельный сервис внутри
сети Docker. Это архитектурно гибче, чем Apache+PHP в одном контейнере:
сервисы можно независимо собирать, перезапускать, масштабировать и
конфигурировать.

## 2

![2](/screenshots/2.png)

Если сначала выполнить COPY всего проекта, то любое изменение в коде будет инвалидировать слой Docker и composer install
запустится заново. Поэтому сначала копируются только composer.json и composer.lock: пока зависимости не менялись, Docker
использует кешированный слой composer install.

## 3

![3](/screenshots/3.png)

Если не исключить .env из Docker-образа, секреты приложения попадут внутрь образа: пароли БД, ключи приложения и токены. Такой
образ можно случайно отправить в registry или передать другому человеку, что приведёт к утечке конфиденциальных данных.

## 4

![4](/screenshots/4.png)

Версии зависимостей фиксируются, чтобы сборка образа была воспроизводимой. Если использовать latest или не фиксировать версии, через год Docker-сборка может
подтянуть новые несовместимые версии библиотек, из-за чего приложение перестанет запускаться без изменений в коде.

## 6

![6](/screenshots/6.png)

Uvicorn должен слушать 0.0.0.0, потому что внутри контейнера это означает все сетевые интерфейсы контейнера. Если указать 127.0.0.1, сервер будет доступен
только внутри самого контейнера, и другие контейнеры Docker-сети, например Nginx, не смогут подключиться к FastAPI.

## 7

![7](/screenshots/7.png)

В Docker-сети контейнеры обращаются друг к другу по именам сервисов из docker-compose.yml. Поэтому Nginx использует laravel:9000 и fastapi:8000, а не
127.0.0.1. Адрес 127.0.0.1 внутри контейнера указывает на сам контейнер Nginx, а Docker DNS автоматически резолвит имена сервисов в IP нужных контейнеров.

## 10

![10](/screenshots/10.png)

Если убрать mysql_data и выполнить docker compose down, данные MySQL будут потеряны вместе с контейнером, если они хранились только в его файловой системе.
Именованный volume управляется Docker и переживает пересоздание контейнеров. Bind-mount привязывает конкретный путь на хосте к пути в контейнере, а named
volume хранится в Docker storage и не зависит от структуры проекта.

## 11

![11](/screenshots/11.png)

depends_on без healthcheck гарантирует только порядок запуска контейнеров, но не готовность сервиса принимать подключения. Из-за этого Laravel или FastAPI
могут стартовать раньше MySQL или Redis и получить ошибку подключения. Healthcheck убирает эту race condition: зависимые сервисы запускаются только после
healthy-статуса БД и Redis.

## 12

![12](/screenshots/12.png)
![13](/screenshots/13.png)

init.sql выполняется только при первом запуске MySQL-контейнера, когда каталог данных ещё пустой. После инициализации данные хранятся в volume mysql_data, и
повторные запуски контейнера уже не выполняют файлы из /docker-entrypoint-initdb.d. Если изменить init.sql после первого запуска, изменения не применятся
автоматически: нужно удалить volume или выполнить SQL вручную.

## 13

![14](/screenshots/14.png)
![15](/screenshots/15.png)

Корневой .env используется Docker Compose для параметров инфраструктуры: паролей и пользователя MySQL. boardy-laravel/.env используется самим Laravel-
приложением. DB_HOST=mysql и REDIS_HOST=redis указываются потому, что внутри Docker-сети сервисы доступны по именам контейнеров, а 127.0.0.1 внутри
контейнера означает сам контейнер, а не MySQL или Redis.

## 15

![17](/screenshots/17.png)
![18](/screenshots/18.png)

docker compose exec выполняет команду внутри уже запущенного контейнера сервиса. docker compose run создаёт новый одноразовый контейнер на основе сервиса и
запускает команду там. Для миграций в текущем окружении удобнее exec, потому что команда выполняется в уже работающем Laravel-контейнере с теми же
подключениями к MySQL и Redis.

## 18

![23](/screenshots/23.png)

docker compose down -v удалит не только контейнеры и сеть, но и named volumes. В этом проекте это приведёт к удалению данных MySQL и Redis, включая
пользователей, посты, комментарии и OAuth-таблицы. Опасность флага -v в том, что он стирает состояние приложения, которое обычно должно переживать перезапуск
контейнеров.

## 19

![24](/screenshots/24.png)

Централизованные логи Docker удобнее, потому что docker compose logs собирает вывод всех сервисов проекта в одном месте и помечает строки именем сервиса. Не
нужно вручную искать разные файлы логов на хосте и запускать несколько tail -f. Можно быстро смотреть весь стек целиком или фильтровать конкретный сервис,
например docker compose logs laravel.

## 20

![25](/screenshots/25.png)

```bash
cp .env.example .env
cp boardy-laravel/.env.example boardy-laravel/.env
docker compose up -d --build
```

Эта команда поднимает проект на новой машине после клона: Compose собирает образы, создаёт volumes, запускает MySQL/Redis, Laravel применяет миграции и
инициализирует Passport. Сейчас изменения задания 20 не закоммичены, закоммичу перед следующим заданием.
