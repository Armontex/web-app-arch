## 10

1. В vanilla JS состояние размазано между переменными и DOM, а в React оно централизовано в state

2. В vanilla JS DOM обновляется вручную, в React через изменение state с автоматическим обновлением интерфейса

3. В vanilla JS редактирование сильно завязано на ручное взаимодействие с DOM, а в React оно описывается через состояние

4. В vanilla JS защита полностью на разраба и зависит от безопасной работы с DOM. В React базовая защита встроена в механизм рендера

## 13

![15](/screenshots/15-xss.png)

В Vanilla JS мы сами пишем esc чтобы экранировать символы, а в react весь пользовательский ввод по-умолчанию такой. В react надёжнее, потому что там экранирование по-умолчанию включено, а в Vanilla JS разработчик должен сам контролировать, чтобы везде где есть пользовательский ввод была функция esc

## 14

|                           | SSR (PHP)           | vanilla JS               | React              |
| ------------------------- | ------------------- | ------------------------ | ------------------ |
| Кто рендерит HTML         | Сервер              | Браузер (JS + innerHTML) | Браузер (React)    |
| Формат ответа сервера     | HTML                | JSON                     | JSON               |
| View Source: данные       | Да                  | Нет                      | Нет                |
| Перезагрузка при отправке | Да                  | Нет                      | Нет                |
| Защита от XSS             | Экранирование в PHP | Функция esc()            | Авто‑экранирование |
| Сложность кода            | Средняя             | Высокая                  | Высокая, но чище   |
